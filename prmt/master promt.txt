# 5. Business Rules

ต้อง Implement Business Rules เหล่านี้จริง

BR4:
การยืมอุปกรณ์กีฬา สามารถทำได้เฉพาะผู้ที่มี Booking สนามในวันและเวลานั้น

BR5:
หากอุปกรณ์ชำรุดหรือสูญหาย ต้องคิดค่าปรับตามราคาประเมินของอุปกรณ์

BR6:
หากยกเลิก Booking ตามเงื่อนไข จะได้รับเงินคืน 80%

BR7:
ต้องคืนอุปกรณ์ภายในเวลาสิ้นสุด Booking

BR8:
สมาชิกจองสนามล่วงหน้าได้ไม่เกิน 30 วัน

BR9:
แก้ไขวันหรือเวลาการจองได้เฉพาะก่อนเวลาใช้งานอย่างน้อย 24 ชั่วโมง

BR10:
ระบบต้องสร้าง Notification เมื่อ Booking หรือ Payment เสร็จสมบูรณ์

BR11:
ลูกค้าสามารถ Check-in ก่อนเวลาเริ่มใช้งานได้ไม่เกิน 30 นาที

BR12:
เฉพาะ ADMIN เท่านั้นที่สามารถเพิ่ม แก้ไข หรือลบข้อมูลสนาม

BR13:
เฉพาะ ADMIN เท่านั้นที่กำหนด Pricing และ Promotion

BR14:
Promotion ใช้ได้เฉพาะช่วงวันที่และเวลาที่กำหนด

BR15:
ระบบต้องบันทึกประวัติ Booking, Payment และ Cancellation เพื่อใช้ตรวจสอบย้อนหลัง

# 6. Demo Requirement

ระบบต้องสามารถ Demo ตามลำดับ:

BEFORE

แสดง:
- สนามว่าง
- จำนวน Equipment ก่อนทำรายการ
- จำนวน Booking
- รายได้
- สถานะสนาม

MAIN FUNCTION

ทำผ่าน UI จริง:

Login
→ Search Court
→ เลือก Sport
→ เลือก Date
→ เลือก Time
→ เลือก Court
→ เลือก Equipment
→ ดูราคา
→ Confirm Booking
→ Upload Payment Slip
→ Staff ตรวจสอบ
→ Verify Payment
→ Booking Confirmed
→ Receipt
→ Notification
→ Check-in
→ Borrow Equipment
→ Return Equipment

AFTER

เปิด Database ตรวจสอบข้อมูลที่เปลี่ยนจริง เช่น:

BOOKINGS
BOOKING_EQUIPMENT
EQUIPMENT_BORROWINGS
PAYMENTS
RECEIPTS
NOTIFICATIONS
AUDIT_LOGS

REJECTION

ต้องมี Demo Business Rule ที่ระบบปฏิเสธ เช่น:

Booking สนามเดียวกัน เวลาเดียวกัน

ระบบต้อง:
- Reject
- แสดง Error Message
- ไม่สร้าง Booking ใหม่
- ไม่ตัด Equipment
- ไม่สร้าง Payment
- ไม่เปลี่ยนข้อมูลที่ไม่เกี่ยวข้อง

FINAL RESULT

แสดง Dashboard/Report ที่สะท้อน Transaction ที่เพิ่งทำ

# 7. Coding Rules

ทุก Phase:

1. อ่านโค้ดปัจจุบันก่อนแก้
2. ห้ามลบระบบเดิมโดยไม่จำเป็น
3. ห้ามสร้าง Duplicate Component
4. ห้ามสร้าง Duplicate API
5. ห้ามสร้าง Duplicate Table
6. ใช้ Naming Convention เดียวกัน
7. ใช้ TypeScript
8. Validate Input ทุก Endpoint
9. Handle Error อย่างเหมาะสม
10. ห้าม Hardcode Secret
11. ใช้ Environment Variables
12. ห้ามใช้ Mock Data เมื่อระบบจริงพร้อมใช้งาน
13. ถ้าต้องใช้ Seed Data ให้ระบุชัดเจนว่าเป็น Development Seed
14. ทุก Database Transaction ต้องมี Commit/Rollback ที่ถูกต้อง
15. ต้องป้องกัน Race Condition ใน Booking และ Equipment Stock
16. ต้องตรวจ Authorization ทุก Protected API
17. ต้องไม่ให้ CUSTOMER เรียก ADMIN API ได้
18. ต้องไม่แก้ Schema ที่มีอยู่โดยไม่มีเหตุผล
19. ก่อนจบ Phase ต้องทดสอบระบบ
20. ห้ามบอกว่า "เสร็จแล้ว" หากยังไม่ได้ทดสอบจริง

เวลานำเสนอ: 10 นาที ต่อกลุ่ม

นักศึกษาต้องนำเสนอให้เห็นว่า ปัญหาคืออะไร ออกแบบฐานข้อมูลอย่างไร และระบบใช้งานได้จริง โดยต้องสาธิต ฟังก์ชันหลักของระบบ ให้ทำงานสำเร็จผ่าน UI เช่น ระบบจองโรงแรมต้องจองห้องได้ ระบบขายสินค้าต้องขายสินค้าได้

1. โครงการนำเสนอ
ช่วง	สิ่งที่ต้องนำเสนอ
1. ที่มาและขอบเขต	ปัญหา ผู้ใช้ระบบ และระบุชัดว่าฟังก์ชันหลักของระบบคืออะไร
2. ER Diagram	entity และความสัมพันธ์ โดยเน้นส่วนที่เกี่ยวกับฟังก์ชันหลัก
3. Schema และ Normalization	ตาราง, PK/FK, constraints และตัวอย่าง normalize 1 ตาราง
4. Demo ฟังก์ชันหลัก	ทำฟังก์ชันหลักผ่าน UI ให้สำเร็จ 1 รอบ (ดูหัวข้อที่ 2)
5. SQL เบื้องหลัง	query หรือ transaction ที่ทำงานอยู่เบื้องหลังฟังก์ชันหลัก
6. สรุป	ปัญหาที่เจอ ข้อจำกัด และการแบ่งงานในทีม
2. ขั้นตอนในช่วง Demo
ไม่ต้องสาธิตการเพิ่ม/แก้ไข/ลบข้อมูลพื้นฐาน (เช่น เพิ่มลูกค้า เพิ่มสินค้า) ให้เตรียมข้อมูลไว้ล่วงหน้า แล้วสาธิตตามลำดับดังนี้

ลำดับ	สิ่งที่ต้องทำ
1. ก่อนทำ	แสดงสถานะเริ่มต้นบน UI เช่น ห้องว่าง หรือจำนวนสต็อกสินค้า
2. ทำฟังก์ชันหลัก	ทำผ่าน UI ตั้งแต่ต้นจนจบในบทบาทผู้ใช้จริง
3. หลังทำ	เปิดฐานข้อมูลให้เห็นว่าข้อมูลเปลี่ยนในทุกตารางที่เกี่ยวข้อง
4. กรณีที่ระบบต้องปฏิเสธ	ทำรายการที่ผิดกฎทางธุรกิจ 1 กรณี แล้วให้เห็นว่าระบบป้องกันได้
5. ผลลัพธ์ปลายทาง	หน้าสรุปหรือรายงานที่สะท้อนรายการที่เพิ่งทำ
3. ตัวอย่างฟังก์ชันหลักตามประเภทระบบ
ระบบ	ฟังก์ชันหลักที่ต้องทำได้	ตารางที่ควรเปลี่ยน	กรณีที่ต้องปฏิเสธ
จองโรงแรม	ค้นหาห้องว่างตามวันที่ → เลือกห้อง → ยืนยันการจอง	การจอง, รายละเอียดการจอง, สถานะห้อง/การชำระเงิน	จองห้องเดิมในช่วงวันที่ทับซ้อน
ขายสินค้า	เลือกสินค้าหลายรายการ → คิดเงิน → ออกใบเสร็จ	ใบขาย, รายการขาย, สต็อกสินค้า	ขายเกินจำนวนในสต็อก
ห้องสมุด	ยืมหนังสือ → คืนหนังสือ	การยืม, สถานะหนังสือ, ค่าปรับ	ยืมเล่มที่ถูกยืมอยู่ หรือยืมเกินโควตา
ลงทะเบียนเรียน	เลือกรายวิชา → ยืนยันการลงทะเบียน	การลงทะเบียน, จำนวนที่นั่งคงเหลือ	ลงวิชาที่เต็ม หรือเวลาเรียนชนกัน
คลินิก/นัดหมาย	เลือกแพทย์และเวลา → บันทึกนัด	การนัดหมาย, ตารางเวลาแพทย์	นัดเวลาที่มีคิวแล้ว
4. ข้อแนะนำในการนำเสนอ
เลือกเฉพาะจุดเด่น: ไม่ต้องอธิบายทุกตารางหรือทุก attribute ให้เลือกส่วนที่สะท้อนการคิดออกแบบ
อธิบายเหตุผล ไม่ใช่แค่ผลลัพธ์: เช่น ทำไมแยกตารางนี้ ทำไมเลือก PK แบบนี้
สไลด์ประมาณ 8–10 แผ่น: ER Diagram ต้องอ่านออก ถ้าใหญ่มากให้ซูมเฉพาะส่วนสำคัญ

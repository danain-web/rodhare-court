# คู่มือตั้งค่าระบบแจ้งเตือน (in-app + อีเมล) และตัวตั้งเวลา

ระบบแจ้งเตือนทำงานดังนี้

```
cron-job.org (ทุก 5 นาที)  ──POST──►  Render: /api/internal/cron/tick
                                         │ 1) ปล่อยการจองที่ไม่มา (NO_SHOW) / ปิดการจองที่จบแล้ว
                                         │ 2) สร้างแจ้งเตือนล่วงหน้า (24 ชม. และ 60 นาที ก่อนเริ่ม)
                                         │ 3) ส่งอีเมลที่ค้างในคิว ผ่าน Resend
                                         ▼
                              ผู้ใช้เห็นกระดิ่งในเว็บ + ได้อีเมล
```

ทำไมต้องมี cron ภายนอก: Render แบบฟรีจะ "หลับ" เมื่อไม่มีคนเข้าใช้ ตัวตั้งเวลาที่อยู่ในเซิร์ฟเวอร์จึงหยุดทำงานไปด้วย
จึงให้ตัวภายนอกยิงมาปลุกและสั่งงานทุก 5 นาที (ถ้าเซิร์ฟเวอร์ตื่นอยู่แล้ว ตัวตั้งเวลาในโปรเซสก็ทำงานเองทุก 1 นาทีอยู่แล้วด้วย)

---

## ขั้นที่ 1 — รัน migration ใน Supabase (ต้องทำก่อนทุกอย่าง)

เปิด Supabase → **SQL Editor** → New query → วางเนื้อหาไฟล์ใน `database/migrations/` ทีละไฟล์ตามลำดับแล้วกด **Run**

| ไฟล์ | ทำอะไร | ข้ามได้ไหม |
|---|---|---|
| `005_role_permissions.sql` | สิทธิ์เก็บใน DB | ไม่ได้ |
| `006_no_show_and_settings.sql` | สถานะไม่มาใช้บริการ + ตารางตั้งค่า | ไม่ได้ |
| `007_reminders_and_email.sql` | คอลัมน์แจ้งเตือน/คิวอีเมล | ไม่ได้ |

รันซ้ำได้ ไม่ลบข้อมูล ถ้า deploy โค้ดใหม่โดยยังไม่รัน 005–007 ระบบจะ error เพราะหาตาราง/คอลัมน์ไม่เจอ

## ขั้นที่ 2 — สมัคร Resend และเอา API key

1. เข้า <https://resend.com> → **Sign Up** (สมัครด้วยอีเมลที่คุณเข้าถึงได้ — ใช้อีเมลนี้ตอนทดสอบด้วย ดูข้อจำกัดด้านล่าง)
2. ยืนยันอีเมลตามลิงก์ที่ส่งมา
3. เมนูซ้าย **API Keys** → **Create API Key**
   - Name: `rodhare-court`
   - Permission: **Sending access** (ไม่ต้องใช้ Full access)
4. กด **Add** แล้ว **คัดลอก key ทันที** (ขึ้นต้นด้วย `re_...`) Resend แสดงครั้งเดียว ถ้าพลาดให้สร้างใหม่
5. อย่าวาง key ลงแชต, GitHub หรือไฟล์ในโปรเจกต์ ใส่ใน Environment ของ Render เท่านั้น (ขั้นที่ 3)

### ข้อจำกัดสำคัญเรื่องผู้ส่ง (อ่านก่อนสาธิต)
- ถ้ายังไม่ยืนยันโดเมนของตัวเอง ให้ใช้ผู้ส่ง `onboarding@resend.dev` ซึ่งเป็นผู้ส่งสำหรับทดสอบของ Resend
  และ **จะส่งได้เฉพาะอีเมลที่คุณใช้สมัคร Resend เท่านั้น** (ตามเอกสาร Resend ณ ตอนเขียน — ตรวจที่ <https://resend.com/docs> อีกครั้งก่อนสาธิต)
- ดังนั้นตอนสาธิต ให้สมัครบัญชีลูกค้าทดสอบในระบบด้วย **อีเมลเดียวกับที่สมัคร Resend**
- ถ้าอยากส่งถึงใครก็ได้ ต้องมีโดเมนของตัวเอง แล้วไป Resend → **Domains** → Add Domain → เพิ่ม DNS record ที่ให้มา → รอสถานะ **Verified**
  จากนั้นเปลี่ยน `EMAIL_FROM` เป็นอีเมลบนโดเมนนั้น เช่น `Rodhare Court <noreply@โดเมนของคุณ>`
- ฟรีเทียร์: 3,000 ฉบับ/เดือน และ 100 ฉบับ/วัน เพียงพอสำหรับโปรเจกต์นี้

## ขั้นที่ 3 — ใส่ค่าใน Render

Render → service `rodhare-court-api` → **Environment** → Add Environment Variable

| Key | Value |
|---|---|
| `RESEND_API_KEY` | key `re_...` ที่ได้จากขั้นที่ 2 |
| `EMAIL_FROM` | `Rodhare Court <onboarding@resend.dev>` |
| `CRON_SECRET` | ข้อความสุ่มยาว 24+ ตัวอักษร (วิธีสุ่มด้านล่าง) |

สุ่ม `CRON_SECRET` ใน PowerShell:

```powershell
node -e "console.log(require('crypto').randomBytes(24).toString('hex'))"
```

(ถ้า deploy ด้วย `render.yaml` Render จะสร้าง `CRON_SECRET` ให้เอง ดูค่าได้ที่หน้า Environment)

กด **Save Changes** — Render จะ deploy ใหม่ รอจนสถานะเป็น **Live**

หมายเหตุ: ถ้าไม่ตั้ง `RESEND_API_KEY` ระบบยังแจ้งเตือนในแอปได้ตามปกติ แค่ไม่ส่งอีเมล และถ้าไม่ตั้ง `CRON_SECRET` endpoint `/api/internal/cron/tick` จะปิด (ตอบ 404)

## ขั้นที่ 4 — ทดสอบ endpoint ด้วยมือ

ใน PowerShell (แทน `<URL>` ด้วยที่อยู่ Render เช่น `https://rodhare-court-api.onrender.com` และ `<SECRET>` ด้วยค่า `CRON_SECRET`):

```powershell
Invoke-RestMethod -Method Post -Uri "<URL>/api/internal/cron/tick" -Headers @{ "x-cron-secret" = "<SECRET>" }
```

ผลที่ถูกต้อง: ได้ JSON ที่มี `"success": true` และ `data` เช่น `expired`, `noShow`, `remindersFirst`, `emailsSent`, `errors: []`

| ผลที่ได้ | สาเหตุ |
|---|---|
| 401 | `CRON_SECRET` ที่ส่งไม่ตรงกับที่ตั้งใน Render |
| 404 | ยังไม่ได้ตั้ง `CRON_SECRET` หรือ Render ยังไม่ deploy เสร็จ |
| ช้า 30–60 วินาทีครั้งแรก | Render กำลังตื่นจากหลับ (ปกติ) |
| `errors` ไม่ว่าง | ดูข้อความ ถ้าบอกว่าไม่พบตาราง/คอลัมน์ แปลว่ายังไม่ได้รัน migration |

## ขั้นที่ 5 — ตั้งตัวตั้งเวลาที่ cron-job.org

1. เข้า <https://cron-job.org> → **Sign up** (ฟรี) → ยืนยันอีเมล → Log in
2. กด **CREATE CRONJOB**
3. แท็บ **Common**
   - Title: `rodhare tick`
   - URL: `<URL>/api/internal/cron/tick` (ที่อยู่ Render ตรงๆ ไม่ผ่าน Vercel)
   - Execution schedule: เลือก **Every 5 minutes**
4. แท็บ **Advanced**
   - Request method: **POST**
   - Headers → **Add**: Key = `x-cron-secret`, Value = ค่า `CRON_SECRET`
   - (ถ้ามี) Request body เว้นว่างได้
5. กด **CREATE** แล้วกด **TEST RUN** ต้องได้ HTTP **200**
6. ดูประวัติที่ **History** ของ job ถ้าเป็น 401/404 ให้ย้อนไปตรวจขั้นที่ 3–4

ข้อสังเกต: การยิงทุก 5 นาทีทำให้ Render ฟรีไม่หลับตลอดเวลา (ใช้ชั่วโมงฟรีมากขึ้น แต่ 1 service ทั้งเดือนยังอยู่ในโควตา 750 ชั่วโมง)
ถ้าครั้งแรก cron-job.org ขึ้น timeout เพราะ Render กำลังตื่น ไม่เป็นไร รอบถัดไปจะสำเร็จเอง

## ขั้นที่ 6 — ทดสอบทั้งระบบ

1. สมัครบัญชีลูกค้าด้วยอีเมลเดียวกับที่สมัคร Resend
2. จองสนามช่วงเริ่มในอีกประมาณ 50 นาที ชำระเงินจนสถานะเป็น `CONFIRMED`
3. รอ cron รอบถัดไป (ไม่เกิน 5 นาที)
4. ควรเห็น: กระดิ่งในเว็บมีแจ้งเตือน "ใกล้ถึงเวลาใช้สนามแล้ว!" และได้อีเมลหัวข้อ `[Rodhare Court] ...`
5. ปล่อยให้เลยเวลาเช็กอิน (ค่าเริ่มต้นหลังเริ่ม 15 นาที) → สถานะเป็น "ไม่มาใช้บริการ" พร้อมแจ้งเตือนและอีเมล

ดูผลการส่งที่ Resend → **Logs** (สถานะ Delivered / Bounced) ถ้าอีเมลไม่เข้า ลองดูโฟลเดอร์สแปม

### ปรับเวลาแจ้งเตือน/เช็กอิน
เข้าเว็บด้วยบัญชี admin → เมนู **ตั้งค่าระบบ** แก้ได้เลย ไม่ต้อง deploy ใหม่

| ค่า | ความหมาย | ค่าเริ่มต้น |
|---|---|---|
| `reminder.first_hours` | เตือนครั้งแรกก่อนเริ่มกี่ชั่วโมง | 24 |
| `reminder.second_minutes` | เตือนครั้งที่สองก่อนเริ่มกี่นาที | 60 |
| `checkin.early_minutes` | เช็กอินได้ก่อนเริ่มกี่นาที | 15 |
| `checkin.late_minutes` | เช็กอินได้หลังเริ่มกี่นาที (เลยแล้วถือว่าไม่มา) | 15 |

## หลักการทำงาน (สำหรับอธิบายอาจารย์)

- **ไม่ส่งซ้ำ:** การจองมี `reminder_first_sent_at` และ `reminder_second_sent_at` ตั้งค่าในธุรกรรมเดียวกับที่สร้างแจ้งเตือน และใช้ `FOR UPDATE SKIP LOCKED` กันงานที่รันซ้อนกัน
- **จองใกล้เวลา:** ถ้าจองตอนเหลือ 30 นาที จะได้เฉพาะแจ้งเตือนรอบสอง ไม่ได้สองข้อความติดกัน
- **อีเมลแบบคิว (outbox):** แจ้งเตือนในแอปถูกบันทึกก่อนเสมอ แล้วตัวส่งอีเมลมาเก็บไปส่งทีหลัง ถ้าอีเมลล้มจะลองใหม่สูงสุด 3 ครั้ง และไม่กระทบการจองหรือแจ้งเตือนในแอป
- **ปลอดภัย:** endpoint ตรวจ secret แบบ timing-safe, เนื้อหาอีเมล escape HTML, ไม่เก็บ API key ในโค้ด, ในโหมดเทสต์ไม่ส่งอีเมลจริง

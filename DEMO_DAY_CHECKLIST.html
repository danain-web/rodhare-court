5. SQL เบื้องหลัง (เปิดโค้ดโชว์ 1 นาที)

  • Transaction การจอง: backend\src\services\booking.service.ts ฟังก์ชัน createBooking — ล็อกสนาม ตรวจกฎ BR2/BR4 แล้ว insert BOOKINGS + BOOKING_EQUIPMENT ตัดสต็อก EQUIPMENT ใน transaction เดียว ถ้าขั้นไหนพลาด rollback ทั้งหมด
  • Trigger กันจองซ้อน: database\constraints.sql → trg_bookings_no_overlap (Compound Trigger ล็อกแถว COURTS แล้วตรวจเวลาทับซ้อน)
  • Constraints เด่น: chk_bk_final (ยอดสุทธิ = ค่าสนาม + ค่าอุปกรณ์ − ส่วนลด), chk_eq_stock (สต็อกห้ามติดลบ), uq_pay_slip_ref (สลิปห้ามซ้ำ), uq_users_username_ci (ชื่อผู้ใช้ห้ามซ้ำแบบไม่สนตัวพิมพ์)

7. คำถามที่น่าจะโดนถาม

กันจองซ้อนอย่างไร?
สองชั้น: backend ล็อกแถวสนาม (SELECT … FOR UPDATE) ก่อนตรวจเวลาทับซ้อน และฐานข้อมูลมี trigger trg_bookings_no_overlap ตรวจซ้ำ ต่อให้ insert ด้วย SQL ตรง ๆ ก็จองซ้อนไม่ได้
ไม่จ่ายเงินภายใน 15 นาทีเกิดอะไรขึ้น?
งานเบื้องหลังตรวจทุก 1 นาที เปลี่ยนสถานะเป็น EXPIRED คืนช่องเวลาและคืนสต็อกอุปกรณ์อัตโนมัติ
ตรวจสลิปปลอมได้ไหม?
ตอนนี้ตรวจได้เฉพาะสลิปซ้ำ ยอดเงิน และความชัดของภาพ ยังยืนยันกับธนาคารไม่ได้ว่ามีการโอนจริง ถ้าใช้งานจริงจะต่อ API ตรวจสลิปที่อ่าน QR บนสลิปไปเช็คกับธนาคาร และฐานข้อมูลแยก verification_method AUTO/MANUAL ไว้แล้วเพื่อกระทบยอดย้อนหลัง
ทำไมอยู่ใน 3NF? / ทำไมแยกตารางนี้?
เช่น BOOKING_EQUIPMENT แยกจาก BOOKINGS เพราะหนึ่งการจองยืมได้หลายอุปกรณ์ (1:N) และเก็บ unit_rental_fee ณ เวลาจอง ทำให้ราคาที่ตกลงไว้ไม่เปลี่ยนตามราคาปัจจุบันใน EQUIPMENT
Audit Log บันทึกอย่างไร?
ทุกตารางมี trigger trg_<table>_audit บันทึก INSERT/UPDATE/DELETE ลง AUDIT_LOGS พร้อมค่าเก่า/ค่าใหม่เป็น JSON และผู้ทำรายการ (จาก CLIENT_IDENTIFIER ที่ backend ตั้ง)
ราคาคิดอย่างไร?
ราคาสนามตามช่วงเวลาและประเภทสมาชิกจาก PRICING_RATES (ไม่มีอัตราพิเศษใช้ราคาพื้นฐานของสนาม) หักส่วนลดตาม MEMBER_TYPES (นักศึกษา 10%, บุคลากร 15%) บวกค่าเช่าอุปกรณ์
ยกเลิกแล้วคืนเงินเท่าไร?
ยกเลิกล่วงหน้ามากกว่า 24 ชม. คืน 100% / 1–24 ชม. คืน 50% / น้อยกว่า 1 ชม. ไม่คืน (BR12) และช่องเวลากลับมาว่างทันที
